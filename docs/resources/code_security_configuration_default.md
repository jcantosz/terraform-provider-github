# github_code_security_configuration_default (Resource)

Manages one configuration's default for **new** repositories. See the
[GitHub API permissions and prerequisites](https://docs.github.com/en/rest/code-security/configurations#set-a-code-security-configuration-as-a-default-for-an-organization).
This does not attach the configuration to existing repositories.

`default_for_new_repos` accepts `all`, `public`, `private_and_internal`, or
`none`. `none` declaratively ensures this configuration is not a default.
Deleting this resource sets the scope to `none`, without deleting the
configuration or detaching existing repositories.

Scopes of defaults for different configurations must not overlap. GitHub can
replace another configuration's default when setting an overlapping scope.
Use one owner for these settings; do not declare conflicting defaults or
manage the same configuration's default in multiple resources.

## Example Usage

```terraform
resource "github_code_security_configuration" "example" {
  name        = "Public repository baseline"
  description = "Code security defaults for new public repositories"
}

resource "github_code_security_configuration_default" "example" {
  configuration_id      = github_code_security_configuration.example.id
  default_for_new_repos = "public"
}
```

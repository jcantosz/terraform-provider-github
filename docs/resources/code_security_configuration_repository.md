# github_code_security_configuration_repository (Resource)

Manages one selected repository relationship, not the configuration's entire
repository membership. Other attachments are left untouched. See the
[attach](https://docs.github.com/en/rest/code-security/configurations#attach-a-configuration-to-repositories)
and [detach API permissions and prerequisites](https://docs.github.com/en/rest/code-security/configurations#detach-configurations-from-repositories).

Attachment is asynchronous. Create polls queued, `attaching`, and `updating`
relationships until GitHub reports `attached`, `enforced`, or
`enterprise_enforced`. The provider also waits when refreshing an in-progress
relationship and after detachment. These bounded waits honor context
cancellation; the `create`, `read`, and `delete` timeouts default to five
minutes and can be overridden in a `timeouts` block. A processing relationship
is not silently removed from state while a job is queued. Failed jobs return
diagnostics and retain the relationship ID; resolve GitHub's configuration
prerequisites before replacing the resource.

Completion polling is specific to GitHub's asynchronous attachment/detachment
jobs, not a blanket resource Read after writes. A queued or processing detach
does not clear the relationship ID until its removal is confirmed.

`status` records GitHub's observed attachment state. `detached`, `removed`, and
`removed_by_enterprise` mean the relationship no longer exists and are removed
from state on refresh. Feature enablement within repositories can still be
subject to GitHub's own processing after the attachment becomes active.

Destroy detaches the repository without deleting it or the configuration.
Detach does not promise to disable previously enabled security features.
Enforced or enterprise-managed configurations can restrict detachment; API
errors are returned without silently forgetting the relationship.
Before detaching, the provider checks membership to avoid detaching a
configuration assigned by another actor. GitHub has no conditional detach
endpoint, so concurrent reassignment between that check and detach remains
unsafe. Do not concurrently manage this repository's attachment elsewhere.

Only selected repository IDs are supported. Bulk script scopes (`all`,
`all_without_configurations`, `public`, `private_or_internal`) describe
one-time actions, not persistent relationships and are intentionally not
exposed. Enumerate the intended repositories with `for_each`; manage future
repositories using
[github_code_security_configuration_default](code_security_configuration_default).
Do not declare multiple attachments for the same repository, including across
different configurations.

## Example Usage

```terraform
resource "github_code_security_configuration" "example" {
  name        = "Selected repository baseline"
  description = "Code security configuration for selected repositories"
  enforcement = "unenforced"
}

resource "github_repository" "example" {
  name       = "example"
  visibility = "private"
}

resource "github_code_security_configuration_repository" "example" {
  configuration_id = github_code_security_configuration.example.id
  repository_id    = github_repository.example.repo_id
}
```
